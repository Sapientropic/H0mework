# CI 与增量构建

[`ci.yml`](../.github/workflows/ci.yml) 处理 `main` 推送、PR 更新和手动运行。README、横幅、许可及作者指南的纯展示改动不触发工作流，冻结来源文档仍参与检查。同一分支或 PR 的新推送取消旧运行，被取消的 Lean job 先保存已完成的产物。

## 何时构建 Lean

是否构建由内容决定，与本次推送改了哪些文件无关。[`ci_plan.py`](../tools/ci_plan.py) 为每片计算指纹，再合成完整选集指纹。完整选集指纹由以下内容生成：

- 全部分片指纹；
- 工具链与 manifest；
- 规划脚本与两个工作流文件。

完整选集在一次运行中全部构建，并通过 `lake --no-build build` 后，才以该指纹写入一条验收记录。之后同一内容的运行查到记录，就跳过 Lean。被取消、失败或到期的运行不写这条记录，下一次运行会重新检查。

冻结证据 job 每次运行导出映射校验、低能唯象复核与工具测试。私有期间，Lean 只在手动运行时执行。

## 分工

`make_plan` 从 `lakefile.toml` 的默认库及真实 import 计算模块闭包，沿用各模块的资源依赖、编译参数与库归属。非默认的历史失败库继续通过复现指南中的命令检查。

构建按依赖顺序分为共享基础、并行分片和论文入口汇总三段：

- **共享基础**：`partition` 将跨分片依赖的闭包归入这里，只编译一次。
- **并行分片**：
  - 化学中的分组计算按组号分成四片，其余分片覆盖算术、Navier–Stokes、物理和结构模块。
  - 汇总中只依赖共享基础的模块组成独立片，与其他分片同时运行。论文入口除外，新增论文只改变汇总的指纹。
  - 分片不设并发上限。
- **汇总**：读取本次运行中上游已验收的产物，完成后要求全部配置的默认目标均已满足。

## 跨运行续建

冷构建的总量远超单个 job 的 6 小时上限，所以每片可以分多次运行完成：

- 每个 job 开始约 5 小时 20 分后停止构建，留出打包和保存的时间。
- 构建完成时，产物存为该片的精确键；失败、到期或被取消时，存为附带运行编号的进度键。
- 恢复顺序为精确键、同一指纹最新的进度、该片最新的任一版本。恢复后由 Lake 的 trace 决定哪些模块仍需编译，缓存不会绕过源码与资源检查。
- 精确键只在整片构建成功后写入，所以命中精确键的分片直接把存档交给下游，不再安装 Lean。
- `main` 上若有分片到期停止且本次有新进度，工作流自动续跑，最多 12 次；续跑排在当前运行之后。到期时一个模块都没完成，则报错停下，不再续跑。

## 缓存与资源

[`lean-part.yml`](../.github/workflows/lean-part.yml) 分别缓存固定依赖与各片证明产物。依赖缓存按平台、工具链及 manifest 区分。证明缓存键由该片模块、传递依赖、实际资源内容和有效编译配置生成，提交号与展示文档的变化不改变它。

分片存档保存所属模块的 `.olean`、`.ilean`、生成 C、trace 与哈希文件，排除临时 `.setup.json`，使用 zstd 压缩。job 间传递的短期工件保存一天。`completed_setup_files` 仅清除已有更新编译 trace 的 setup 文件，避免删除仍在使用的编译输入。

GitHub 缓存容量及七天未访问回收规则见[官方缓存说明](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching#usage-limits-and-eviction-policy)。本仓配置不增加收费缓存容量。

本地查看分工、检查一片已有产物：

```bash
python3 tools/ci_plan.py plan
python3 tools/ci_plan.py build --part physics --check-only
```
