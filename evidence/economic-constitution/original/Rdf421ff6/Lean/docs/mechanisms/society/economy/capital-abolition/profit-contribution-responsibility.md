## 载体与来源

所有读数都从原 `RawLaw.rawItems`、原 `Financial.accountAt`／实际 cursor 的 native GS
以及同一原发生的 controller sites 生成。资产、负债、已付额和归档保原 instrument、unit、rate、

## 四分会计收益

对固定原 word、每个原 Party／Good，逐项穷尽八类 operation 的实际作用：

```text
fullIncome = productiveNet + otherTransfers + controlIncome
bookIncome = openingPrice × productiveNet
           + openingPrice × otherTransfers
           + openingPrice × controlIncome
           + revaluation
```

`productiveNet`只累计真实产出减生产、使用和修订的实际成本。
issue、settle、assign及内部转移的社会净物量为0；settle 的现金同时冲减原请求权，不能把本金重复计利。
native opening 读取原所有槽的资产／负债；估值差在原 closing position 之后单独计算。

control 项来自原 kernel checked image 的实际 item index 与原 controller 地址；其余转移保在完整补项。
它不是全部经济租金的因果归因，也不把收款人坐标当成个人生产贡献。
转移仍可改变个人退出能力；社会净物量为0不推出个人未来锥不变。
空词持有不生成新的生产或转移，只可能产生估值收益。

任意原 lawful word 的公开控制解释保同一 items、next、全部净生产和全账户作用；
贡献功能因而可以实际保留，而不以永久准入控制作为其必要条件。

权威口：`Profit.the_original_book_return_has_its_complete_four_component_decomposition`、
`Profit.every_original_lawful_contribution_keeps_its_effect_and_full_account_without_control`。

## 有限请求权不靠换槽复活

原每槽的实际 native Run 给出：

```text
remainingPrincipal + actualReceived = originalPrincipalAtCut
```

原 source 的 inventory、readIssue、跨visit严格发生顺序、实际 cursor prefix，
共同生成账户 origin 不重复；这是 producer，不是 caller 提供的 NoDup。
ActualPast和PublicPast直接折叠既有 consumeVisit；每个原位置只出现一次，两个法域阶段不混同。
Legacy只运输整枚原 GS，不重建 live account。

因此按同原 origin 汇总终点**全部槽**，实际累计受领不超过原 source quantity。
新 admission、转让、等待及其他债的支付不能给原贡献充值。
原 principal／risk archive 沿任意 native Run 保整枚收据，其原槽后续实付为0。

泛型 `.admit Claim`允许重复；机器反例专门保留这一点。
总界的公开口消费实际 source／cursor／公开前缀，不能把泛型 Run 偷换成原实际发行路径。
有限总额也不等于有限时钟；真正无界累计索取才与该上界矛盾。
ordinary standing、赠与及新的实际服务不被改写成“所有收入都须来自本期劳动”。

权威口：`Contribution.Source.every_actual_cursor_continuation_bounds_the_whole_original_contribution`、
`Contribution.EpochHistory.every_actual_public_suffix_bounds_the_entire_original_contribution`；
原 Engine 的直接消费为 `EpochHistory.Actual.every_original_innovation_public_suffix_bounds_the_whole_original_contribution`。

## 净阻塞原生成为责任

逐原受损者与物量单位：

```text
q(person,good) = max 0 (productiveOpen(person,good) - productiveControlled(person,good))
```

两支保同 seed、原未知请求、融资、试验、本方信息与实际历史反应；反应造成的费用也进入各自原 trace。
先把 permission loss 与 policy loss 分开，不能把全部差额随手归给第一个 controller。
controller cohort由原受阻 port 与拒绝项生成，其 actor 仍是该原发生的 ActualBirth。

生产流的有限支持自产完整 positiveScope；任意 Party／Good 的正损害都有覆盖证明。
一枚 `Family.Claim`拥有整个矩阵及一个 raw cursor，不为每个受损者复制世界。
该原生责任不是控制者自愿签名的 loan。

一次实际补偿更新每个原 key：

```text
credit(key) = max 0 (actualAfter.stock(key) - actualBefore.stock(key))
remaining'(key) = max 0 (remaining(key) - credit(key))
```

source检查先排除IOU／转让／无关融资。真实补偿只消费原控制cohort的物料与原受损项，
需要的执行权限由当前实际 law 提供，不要求旧控制者同意自己的责任。
自己转账净增量为0；给其他人的产出不清本人债；完整成本、消费和对外补偿都扣出本人净增量。
后段请求被拒绝仍保留前段真付，既不抹掉支付，也不虚构整词成功。

未付时有限扫描直接产生原 key、bearer、Good、word与正残差。
同次独立 Needs 检查生成全员实付或具体生活／维护失败者。
矩阵清零只结清这笔原损害；`SupportTerminalAt`没有全社会终局凭证。
原源实例材料8／5／5、成果2／1／0由同一次实际修复结清，全员生活维护照付，旧金融claims保留。

## 原根、整账与下一次输入

`Source.OriginAt`只认原 law／before／word与已经消费完的原 inventory，不接赔偿量、目标状态或coverage。
同原发生的 opening、四分收益、controller lineage和全矩阵由同一 receipt 索引。
本次实际修复输入显式进入原source coface，再由 inquiry compiler选择 debt-admission action。
原所有行经同一 source successor整账运输，新责任由框架原生 debt admission生成。

命名 canonical runtime实际消费该 action，进入 declared、observed；同root semantic faces读到
实际材料处置与原承担者的 Needs，whole-ledger及 generated next都认回这枚原发生。
历史 inquiry cofaces保原事件读面，不能冒充新未来事件。

重入口从当前原 native debtRow读取 raw与remaining；新实际 word再次进入source coface。
这次走 same-N sequential actualAction：初始整账identity且no-fresh，不再admit、不回atCursor，
只由Family.advance生成新状态。返回的真实row与authority可以继续接下一次实际输入，
不预写未来成功表，也不把当前 typed blocker核销。

主入口：`Root.Action.Runtime.the_original_source_installs_and_consumes_its_complete_accounting`。

原剩余额约束、责任优先现金流、有限清格续约及已清责任不得再提款，统一由
[责任先于资本](responsibility-before-capital.md)的`Accounting.Priority`接入这枚原根；
估值／持有与真实新放款也在该机制卡区分。
