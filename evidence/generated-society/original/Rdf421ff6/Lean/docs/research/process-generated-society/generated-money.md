## 一、最高判断：货币是已结清生成的未消费行动能力

生成型货币不是劳动积分，也不是贴在 result 上的价值标签：

\[
\boxed{
\text{result}\neq\text{currency},
\qquad
\text{result 与 currency 是同一 occurrence 的不同 dependent faces}.
}
\]

proof、知识、软件、模型与公开数据通常是 non-rival results。它们一旦验证，应扩大 commons；真正稀缺并可被
结算的是 compute、review、maintenance、execution、route、service 与下一枚 transformation 的调用能力。

因此：

\[
\boxed{
\operatorname{GeneratedMoneyAt}(c)
\iff
\exists o,\;
\operatorname{SettledGenerationAt}(o)
\land
\operatorname{UnspentActionableRestrictionOf}(c,o).
}
\]

余额、ticker、钱包与法币 quote 都只是 observer readouts。它们不生成 currency authority。

## 二、三条已合流的设计传统

### 2.1 比特币：公开、可复算、无 trusted mint 的 settlement authority

比特币最应继承的是 peer-to-peer payment、double-spend resistance、公开 history 与退出 central mint，而不是
固定总量神话。PoW 的真实结构作用是排序成本、历史抗改写与 issuance/fee settlement；hash 本身不证明科学、
工程、照护或社会 usefulness。

### 2.2 《流放之路》：货币消费就是实际 transformation

currency item 不是统一金币的替身，而是 reroll、add-affix、socket 等 typed operations：

```text
medium of exchange
+ concrete action
+ opportunity cost
+ native sink
+ future-cone modifier
```

它教会我们：货币不只代表 action，消费本身就应执行 action。

### 2.3 M∞：任何 action 都必须支付完整责任

现实中的 productive work 还必须登记 source、bearer、consumer、resource debit、maintenance、failure residual、
whole-ledger write-back 与 generated next。于是最大合成是：

```text
Bitcoin: public settlement / no trusted mint
+ PoE: currency as typed transformation
+ M∞: lineage / residual / renewal / no-section / conditional U8
= generated money
```

## 三、本体纪律：不新建货币世界

\[
\operatorname{RealityRoot}=\Omega.
\]

货币只是 \(\Omega\) 中 actual occurrences 的 dependent face。不得新建 Homework person、currency root、第二
ledger、receipt registry、truth oracle、challenge court 或 completed future。

参与者由 contribution lineage fold 生成；团队/项目身份由 group transport 生成；producer、reviewer、maintainer、
consumer 与 challenger 角色由 relation phase 生成。地址、公钥、GitHub 用户名和账户只是 control/readout keys。

钱包的正确类型是 derived portfolio：

\[
\operatorname{WalletReadoutAt}(O,t)
=
\operatorname{fold}
(\text{visible unspent capability incidences}).
\]

同一 balance 可以来自不同 demand、resource debt 与 residual lineage；balance 不存在 occurrence-authority left inverse。

## 四、共同 source carrier

货币 specialization 的第一枚真实 producer 不是 wallet、ticker 或十八张 certificate，而是一枚安装在既有 Society
root 上的共同 occurrence carrier：

```text
exact installed demand
→ actual execution trace
→ source-fixed verification
→ independent consumer acceptance
→ resource debit / residual disposition
→ non-rival result commons readout
→ scarce unspent capability restriction
→ same whole-ledger write-back / generated next
```

这是一份 implementation contract，不是已存在的 Lean declaration。public constructor 只能接受 source program；
result、capability、verdict、consumer、next 与 success branch 都必须由 exact event 编译出来。

它直接 specialization 已闭合的 Society final grammar：

```text
lawful presentation
| typed rejection + visible residual bearer
| rooted installed action + whole-ledger successor + generated next
| exact representation failure + same-row U8
```

generic action mouth 已经闭合；货币仍欠的是把共同 carrier 安装进去，而不是再造 Homework action compiler。

## 五、result commons 与 scarce claim 必须分权

若 result \(r\) 可无损复制，而 capability incidence \(c\) 消耗稀缺资源：

\[
\operatorname{Copy}(r)\not\Rightarrow\operatorname{DoubleSpend}(c).
\]

默认 disposition：

```text
verified non-rival result → commons
scarce compute/review/maintenance consequence → typed settlement capacity
```

同一 proof 可以被多个 theorem 读取；同一稀缺 review、compute 或 maintenance claim 不能重复花费。知识的复制
不能铸新币，claim 的转让也不能产生知识垄断。

失败同样分权：reusable counterexample/no-go 进入 commons；只有 downstream consumer 实际用它剪枝、节省稀缺
search 或触发 source-owned revision 时，才生成 scarce `NegativeKnowledgeCapacity`。

## 六、typed capacities

生成型货币不是一维万能积分。第一组合法 capability families 可以包括：

```text
ProofCapacity
ComputeCapacity
ReviewCapacity
MaintenanceCapacity
RepairCapacity
DataCapacity
CoordinationCapacity
PublicServiceCapacity
```

每种类型必须固定：

- 可在哪个 carrier 上执行什么 action；
- 谁拥有 exercise authority；
- affected bearer 与 independent consumer；
- spend 时如何写回 whole ledger；
- transfer、expiry、failure 与 residual disposition；
- 打开的 generated next。

不同 capability 只有在真实 coupling occurrence 发生后才产生 exchange relation。局部 numeraire 可以生成，但
scalar quote 始终是 typed market 的上层 readout。

baseline capacity 与 earned capacity 必须分开。基础 renewal 保护 standing bearer 的 role-independent continuation；
贡献生成额外 typed capacity。后者不能成为前者的资格门槛。

## 七、发行、转移、消费与销毁

### 7.1 Mint

```text
exact demand
→ actual execution
→ source-fixed verification
→ independent acceptance
→ resource/responsibility write-back
→ generated unspent capability
```

没有 exact demand、consumer 或 generated next 的 work 不发行。管理员、模型评分器和单一 verifier 都没有 naked
mint authority。

### 7.2 Transfer

transfer 只改变 exercise authority；source provenance、expiry、resource debt、affected bearer 与 residual 不得被洗掉。

### 7.3 Spend

\[
\operatorname{Spend}(c)
\Rightarrow
\text{actual transformation}
\mid\text{accepted maintenance}
\mid\text{typed failure disposition}.
\]

只减 balance 不构成 spend；必须有 actual effect、whole-ledger write-back 与 next。

### 7.4 Split / Merge / Burn

- split 不增加总能力，且必须由原 compiler 生成；
- merge 不擦除任一 source obligation；
- scalar quote 不强迫 typed conversion；
- expiry/burn 不静默删除 bearer、essential exit 或 maintenance debt。

## 八、防双花升级为 no-replay incidence

生成型货币必须同时排除：

1. 同一 settlement face 跨 obligation 重放；
2. 同一 acceptance 在异 occurrence 中复制成两次 issuance；
3. 同一 maintenance action 为不相容责任重复宣称 closure；
4. database duplicate 生成第二 authority；
5. result copy 被误读为 scarce-claim copy。

最大 contract：

\[
\boxed{
\operatorname{Consumes}(s_1,c)
\land
\operatorname{Consumes}(s_2,c)
\Rightarrow
s_1=s_2
\lor
\operatorname{CompilerGeneratedSplit}(c,s_1,s_2).
}
\]

它必须由 exact incidence 与 whole-ledger conservation 证明，而不是数据库 unique constraint。

## 九、“有用”与 challenge authority

\[
\boxed{
\operatorname{UsefulAt}(o)
\iff
\operatorname{ExactDemandAt}(o)
\land
\operatorname{VerifiedEffectAt}(o)
\land
\operatorname{IndependentConsumerAt}(o).
}
\]

“跑了很多 FLOPs”“训练了模型”“写了很多代码”都只是 work readouts。只有 effect 被真实 consumer 使用、资源
结算并生成 next，才取得 money authority。

consumer 存在仍不够。若 demander、producer、consumer 与 challenge authority 被同一封闭联盟垄断，它们可以
自产、自验、自铸。应排除的是 authority closure，而不是机械要求三个不同实名：

\[
\boxed{
\operatorname{ClosedCoalitionAuthorityCompleteMintingAt}=\varnothing.
}
\]

错误或串通 acceptance 被 source-backed challenge 坐实后，consumer 也必须成为 residual bearer，进入撤销、赔付、
冻结、再审或 U8 disposition。admissible 但未成立的 challenge 只 typed-reject，不因“挑战失败”自动惩罚；只有
source-proven replay、串通或 abuse 才产生 debit。

## 十、共识工作与生产工作分权

Proof of Useful Work 不能把以下 mouths 偷换成“都是算力”：

- Sybil resistance / ordering；
- result verification；
- economic usefulness；
- externality accounting；
- maintenance 与 protocol revision。

架构至少分四层：

```text
Settlement plane: ordering / signatures / no-replay / whole ledger
Capability plane: typed demand / result / effect / future action
Exchange plane: transport / credit / clearing / price readout
Constitutional plane: rejection / residual / renewal / U8
```

Homework Coin 首期不需要另造 PoW chain。Git lineage、content hash、Lean kernel、reproducible build 与 signed
consumer acceptance 更贴近作业 occurrence。未来若采用开放共识，security work 与 productive work 仍须分别证明。

## 十一、信用、价格与市场接口

这些机制直接继承经济宪法，只保留货币 specialization：

- future compute/review/maintenance promise 永远标记为 credit，不能冒充 settled capacity；
- claim-on-claim 的每一有限层保留 provenance、collateral、maturity 与 default disposition；
- price 只在 open settlement fibre 上有作用域；
- fiat quote、custody、ETF/wrapper 与 secondary market 不生成 underlying capacity authority；
- protocol 没有价格托底、回购或制造稀缺的 authority。

若技术进步使 `ProofCapacity` 更便宜，这是共同能力增长，不是需要保价的失败。

## 十二、生成型货币 constitutional profile

一枚可被正式接纳的 generated-money implementation 必须同时满足：

1. exact issuance；
2. no replay / compiler-generated split conservation；
3. result commons / scarce claim separation；
4. consumer-generated usefulness；
5. no trusted mint；
6. coalition-open demand 与 challenge authority；
7. consumer liability 与 residual settlement；
8. credit-depth preservation；
9. observer-bounded auditability 与 no-section；
10. baseline exit renewal 与 capture controls；
11. market-interface non-authority；
12. proof-carrying action / rejection / U8 / generated next。

\[
\boxed{
\begin{aligned}
\operatorname{CanonicalGeneratedMoney}(\Omega)
:={}&\operatorname{ExactIssuance}
\land\operatorname{NoReplay}
\land\operatorname{TypedActionability}\\
&\land\operatorname{ResultCommons}
\land\operatorname{IndependentConsumption}
\land\operatorname{ConsumerLiability}\\
&\land\operatorname{CreditDepthPreservation}
\land\operatorname{BaselineExitRenewal}\\
&\land\operatorname{ObserverNoSection}
\land\operatorname{MarketInterfaceNonAuthority}\\
&\land\operatorname{ProofCarryingRevision}
\land\operatorname{GeneratedNext}.
\end{aligned}
}
\]

这是稳定 acceptance profile，不是声称相应 Lean carrier 已经存在。任何实现必须从同一 exact occurrence 正向生成
这些 fields，不能把 profile 本身作为 success premise。
